# Zerocracy в TeamPulse

[Zerocracy](https://www.zerocracy.com) — подход к управлению, где вклад оценивается **за результат, а не за
потраченное время**, по заранее опубликованным правилам, а задачи распределяются автоматически.
TeamPulse реализует три принципа:

1. **Публичная политика баллов** — JSON-файл, одинаковый для всех (`ZEROCRACY_POLICY`, пример —
   [policy.example.json](policy.example.json)).
2. **Прозрачный журнал** — каждое начисление имеет автора, время, причину и ссылку (MR `!12`, задача `#34`,
   коммит). Журнал пересчитывается из исходных данных и полностью воспроизводим.
3. **Автоматическое распределение задач** — система подбирает исполнителя для неназначенной задачи и
   (при `ZEROCRACY_AUTO_ASSIGN=true`) назначает его в Т1 Код.

## Политика по умолчанию

| Событие | Баллы |
|---|---|
| MR влит | +10 |
| Компактный MR (≤ 200 строк) | +5 |
| Огромный MR (> 400 строк) | −5 |
| MR влит без ревью | −3 |
| Участие в ревью чужого MR | +3 и +1 за комментарий (до 5) |
| Закрытая задача | по метке: `size::xs` 2, `size::s` 5, `size::m` 10, `size::l` 20, `size::xl` 30, `bug` 5, `critical` 15; без метки — 5 |
| Коммит со ссылкой на задачу | +1 (не больше 5 в день) |
| Назначенная задача открыта дольше 14 дней | −2 |

Политика поощряет то, что улучшает поток: маленькие MR, ревью коллег, закрытие задач, прослеживаемость.
Строки кода и число коммитов баллов не дают — их легко «накрутить».

## Распределение задач

Для каждой открытой задачи без исполнителя:

- **Экспертиза** (вес 0,6): слова из названия и метки задачи сопоставляются с путями файлов, которые
  разработчик менял за 90 дней (вес — логарифм числа строк), и с метками/названиями закрытых им задач.
  Нормируется к лучшему кандидату (0…1).
- **Загрузка** (вес 0,4): `1 − открытые_задачи / (максимум_по_команде + 1)`.

Итог показывается с объяснением («опыт: parser, backend; загрузка: 1 открытая задача»). Автоназначение
выполняется только если у лучшего кандидата ненулевая экспертиза и известен логин в Т1 Код.

Код — `internal/zerocracy`.
