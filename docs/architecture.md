# Архитектура

## Требования → архитектура → реализация → деплой

| Требование кейса | Архитектурное решение | Реализация |
|---|---|---|
| Автоматический сбор из Git | клонирование и инкрементальный разбор истории | `internal/gitparse` (go-git, pure Go) |
| Интеграция с Т1 Код | интерфейс `Provider` + адаптер GitLab API v4 | `internal/provider` |
| Метрики без ручного вмешательства | планировщик синхронизации и отчётов | `internal/scheduler` |
| Анализ качества, частоты изменений, паттернов | чистые функции над набором данных | `internal/metrics`, `internal/analysis` |
| Отчёты и дашборды | сохраняемый JSON отчёта + рендеринг в 4 формата; SSR-страницы + Chart.js | `internal/report`, `internal/web` |
| Принципы Zerocracy | политика баллов, журнал, распределение задач | `internal/zerocracy` |
| Публичный хостинг | один статический бинарник, SQLite, Docker | `Dockerfile`, `docker-compose.yml` |

## Поток данных

1. **Синхронизация** (`app.Sync`, по кнопке или планировщику): блокировка проекта → `git fetch`/`clone` →
   обход истории, пропуская известные SHA → сохранение коммитов и файлов пачками → загрузка MR и задач из
   Т1 Код, изменённых с прошлой успешной синхронизации → (опц.) автоназначение задач → статус `ok`/`partial`/`failed`.
   Ошибка Т1 Код не теряет данные Git (статус `partial`).
2. **Анализ** (`app.Analyze`): загрузка данных до конца периода → исключение ботов → метрики за период и за
   предыдущий период → тренды → рекомендации → баллы Zerocracy → подбор исполнителей.
3. **Отчёт**: результат анализа сериализуется в JSON и сохраняется; при выгрузке рендерится в HTML/MD/CSV/JSON.

Метрики не хранятся, а считаются на лету из сырых данных — поэтому смена формулы или политики сразу
применяется ко всей истории, а результаты воспроизводимы.

## Модель данных

`projects` → `authors` (+ `author_aliases`: email/логин/имя) → `commits` → `file_changes`;
`merge_requests` → `mr_reviews`; `issues`; `teams` → `team_members`; `reports` (JSON-снимок).
Схема — `internal/storage/migrations/001_init.sql`.

## Ключевые решения

| Решение | Почему |
|---|---|
| Go stdlib `net/http` с маршрутами `GET /projects/{id}` | без фреймворков, достаточно для MVP |
| go-git вместо вызова `git` | нет зависимости от бинарника, работает в distroless |
| SQLite через `modernc.org/sqlite` | без CGO → статическая сборка; одного файла достаточно для MVP |
| Серверный рендеринг + Chart.js (встроен через `embed`) | один бинарник, строгий CSP, минимум JS |
| Расчёт метрик на лету | воспроизводимость и простота изменения формул |
| Интерфейс `Provider` | API Т1 Код можно заменить, не трогая остальной код |
