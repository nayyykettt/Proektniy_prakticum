# Правила безопасности

## Доступ

| Кто | Как входит | Что может |
|---|---|---|
| Пользователь | логин и пароль (регистрация на `/register`) | всё со **своими** проектами: добавление, синхронизация, отчёты, команды, удаление |
| Интеграция | `Authorization: Bearer API_TOKEN` | JSON API ко всем проектам |

- Каждый пользователь видит только проекты, которые добавил сам. Чужой проект по любому адресу
  (страница, отчёт, API) отвечает 404 — как несуществующий. Один и тот же репозиторий разные пользователи
  добавляют независимо.
- Проекты, созданные до появления учётных записей, переходят первому зарегистрированному пользователю.
- Регистрация: логин 3–32 символа (`A-Z a-z 0-9 . _ -`, без учёта регистра), пароль 8–128 символов, повтор
  пароля проверяется в браузере и на сервере. Пароли хранятся как PBKDF2-HMAC-SHA256 (600 000 итераций, соль).
- Сессия — cookie `HttpOnly`, `SameSite=Strict`, `Secure` (при `COOKIE_SECURE=true`), подпись HMAC-SHA256, срок 12 ч.
- Вход и регистрация: не более 10 попыток за 15 минут с одного IP (отдельные счётчики); сравнение за
  постоянное время, для несуществующего логина время ответа выравнивается.
- Редирект после входа — только на локальные пути (защита от open redirect).

## Секреты

- Токены Т1 Код/Git хранятся зашифрованными **AES-256-GCM**; ключ выводится из `APP_SECRET` (HMAC, отдельные
  ключи для шифрования и подписи). Если `APP_SECRET` не задан, секрет генерируется в `DATA_DIR/secret.key` (0600).
- Токены никогда не возвращаются через API и не показываются в формах (поле «оставьте пустым, чтобы не менять»).
- Токен нельзя передать в URL репозитория (`https://user:token@…` отклоняется).
- `.env` и `data/` исключены из Git.

## Входные данные

- URL репозитория и инстанса Т1 Код: только `https`; адреса, разрешающиеся во внутреннюю сеть (loopback,
  private, link-local), запрещены — защита от **SSRF**. Локальные пути — только при `ALLOW_LOCAL_REPOS=true`.
- Имя ветки, название проекта, период, форматы — валидируются; ошибки возвращаются как 400 с понятным текстом.
- Тело запроса ограничено 1 МБ; JSON с неизвестными полями отклоняется.
- SQL — только параметризованные запросы.
- Лимиты: `MAX_COMMITS`, `CLONE_TIMEOUT`, таймауты HTTP-сервера и клиента Т1 Код, повторы с backoff.

## Веб

- **CSRF**: токен в каждой форме (HMAC от сессии); для API по cookie — заголовок `X-CSRF-Token`.
- **CSP**: `default-src 'self'; script-src 'self'; style-src 'self'` — никаких inline-скриптов и стилей; Chart.js
  встроен в бинарник, внешних CDN нет. Отчёт HTML отдаётся с отдельной CSP (только встроенные стили, без скриптов).
- `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`.
- `html/template` экранирует все пользовательские данные (имена авторов, сообщения коммитов, названия задач).
- Внутренние ошибки пишутся в лог, пользователю — общий текст.

## Эксплуатация

- Docker-образ distroless без shell, процесс от пользователя `nonroot`.
- Сервис должен работать за HTTPS-прокси (Caddy/nginx); включите `COOKIE_SECURE=true`.
- Резервная копия — том `/data` (SQLite в режиме WAL).
- Токену Т1 Код достаточно прав `read_api`, `read_repository`; для автоназначения задач — `api`.

## Этика метрик

Метрики предназначены для улучшения процесса, а не для наказания людей. Интерфейс сравнивает команду и
человека с их собственным прошлым периодом, показывает формулы и не строит «рейтинг худших».
